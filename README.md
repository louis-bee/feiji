# 双人飞行日志

飞机与大黄丰的双人生活手账。视觉采用 A「双人飞行日志」：温暖纸色、航迹、原创企鹅与山野插画，移动端优先，同时适配 PC。

## 当前版本

已完成首个可运行版本，使用 Vue 3＋TypeScript＋Vite＋Fastify＋SQLite。不是只靠浏览器存储的演示：日记、媒体、设置与事件由本地 API 持久化，可跨浏览器查看。

| 模块 | 已实现 |
| --- | --- |
| 双人入口 | 选择昵称、前端共用口令、当前标签页刷新保留状态、退出 |
| 首页 | 在一起天数、封面选择、首页寄语、接下来两个重要日子、最近记录、精选媒体 |
| 日历 | 周一起始月历、月份跳转、日期标记、同日多条记录、补记、文字/图片/视频附件、编辑删除、版本冲突检查 |
| 相册 | 图片视频上传、进度/取消/重试、主题相册、归类、说明与日期编辑、精选、大图缩放和原生视频播放 |
| 纪念日 | 双方生日与恋爱周年自动派生、自定义年度/一次性事件、倒计时、过去事件、当天记一笔 |
| 设置 | 昵称、生日、恋爱起始日、业务时区、首页寄语、图片封面 |

尚未加入：单层回复、标签/地点、愿望清单、歌曲卡、地图、完整播放器、自动通知、视频转码、备份、远程部署和 Android 安装包。本轮没有自动提交 Git 或推送。

## 上线与 Android 路线

已确定推荐顺序：**先将 Web 部署到正式 HTTPS 域名，让电脑与双方手机浏览器稳定使用；再制作固定加载该域名的无 ActionBar Android WebView 薄壳。**

- 普通浏览器继续正常访问同一网站，Android App 不复制另一套业务或数据。
- App 正常页面不显示浏览器地址栏、标签页或三点菜单，仅保留系统状态栏和网站自己的导航。
- Web 稳定后，大多数功能更新只发布服务器，不需要更新 APK；文件选择、视频全屏、返回键、图标或原生权限变化才更新 Android 包。
- 首个 Android 版本建议两人侧载 release APK；应用商店、TWA/PWA、相机直拍、通知和离线写入后置。
- 当前公网部署仍面临“前端口令不是真认证”的已知风险，WebView 不会改善它；上线前必须再次知情确认是否保持现状。

完整阶段、部署拓扑、Android 白名单、图片视频上传、返回键、签名分发和验收矩阵见 [Web 上线与 Android 封装计划](docs/android-app-plan.md)。

## 本地运行

要求 Node.js **22.12+**（当前在 22.23.1 验证），以及 npm。

1. 在项目目录执行 `npm ci` 安装锁定依赖。
2. 执行 `npm run dev` 同时启动前端和 API。
3. 打开 <http://127.0.0.1:5173>。
4. 选择“飞机”或“大黄丰”，默认入口口令是 **`0611`**。

口令在 `public/config.json` 的 `entryPassword` 中修改（默认 `0611`）；构建后直接改 `dist/config.json` 即可，无需重新构建。不要复用任何真实账户密码。

开发前端固定端口 5173，代理 API 与媒体到 127.0.0.1:3001。若端口被其他应用使用，不要终止未知进程，应调整 `vite.config.ts` 与 API 的 `PORT`。

### 生产模式本地验证

执行 `npm run build`，然后执行 `npm start`。默认在 <http://127.0.0.1:3001> 同时提供构建产物和 API；无需在线运行 Vite 开发服务器。`tsx` 当前属于运行启动必需工具，按现有脚本安装完整锁定依赖，不使用 `npm ci --omit=dev` 后直接启动。

远程部署尚未执行。后续可在阿里云服务器使用同样的构建产物/代码，经 HTTPS 反向代理访问；Linux 上应重新安装匹配其系统与 CPU 的原生依赖，不复制 macOS 的 `node_modules`。

## 数据与配置

- 她：飞机，生日 `2006-10-25`。
- 我：大黄丰（暂定），生日 `2004-08-11`。
- 恋爱起点：`2026-06-11`，公历，当天算第 1 天。
- 业务时区：初始 `Asia/Shanghai`，可在设置修改。
- 只预置真实双人资料和“日常碎片”默认相册，没有虚构日记、旅行或照片。
- 默认数据库为 `var/journal.sqlite`；运行时 WAL 文件与数据库同目录。
- 媒体在 `var/media/`，与应用构建产物分离。应用重启、前端重建不清除内容。
- 数据库以 SQLite 表存储版本化 JSON 记录；`server/database.ts` 使用 `user_version` 管理 schema 版本（当前 2），并建立日期和相册索引。现阶段是小站全量快照加载，不声称已支持海量数据分页或实时协作。

| 环境变量 | 默认 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | API 监听地址 |
| `PORT` | `3001` | API / 生产静态页面端口 |
| `DATA_DIR` | 项目内 `var` | 持久化目录；建议使用绝对路径 |
| `MAX_UPLOAD_BYTES` | 不设置业务字节上限 | 可选正整数，限制单个文件上传字节数；默认仍受磁盘、网络、代理、运行时限制 |

环境变量由启动环境提供，目前不自动加载 `.env` 文件。不要修改生产 `DATA_DIR` 后误以为旧数据消失；它仍留在原目录。

## 媒体行为与限制

- 图片：JPEG、PNG、WebP、GIF；实际解码校验。非 GIF 生成长边不超过 2000px 的 WebP 浏览图和 480px 缩略图，校正方向；GIF 展示保留动画。
- 不因生成浏览图自动删除原始上传文件；用户明确删除某项媒体时才清理其关联文件。没有原片下载入口。
- 图片工程保护：最多 4000 万解码像素，sharp 单线程并限制缓存；上传同时处理最多 2 个请求，避免在小内存机器上无限堆积。这不是容量规划或新增付费存储。
- 视频：接受识别到的 MP4/WebM/MOV 容器，流式保存与读取，支持 HEAD 和 Range（206/416）。不转码、不做编码级完整探测、不保证所有手机原片可播。
- 推荐 MP4＋H.264＋AAC。HEVC/MOV 等播放取决于浏览器和设备；无法播放时页面给出提示，需自行导出兼容格式。
- 视频列表使用占位封面，不进行服务端截帧；未实现自动获取视频时长、分片续传或 HLS。
- 删除日记不删除媒体；被日记或首页封面引用的媒体禁止直接删除；非空相册需要先移出媒体再删除。
- 浏览器播放/显示媒体必然接收字节，隐藏下载按钮不是防下载措施。

## 访问边界

按要求只做前端口令校验，**不提供真正的私密访问控制**。静态资源可获得口令，路由守卫/身份标记可绕过，API 可直接读写，媒体 URL 可直接访问。参数校验、生成式文件路径和 SQLite 事务只保障程序正确性，不等于鉴权。

没有自动备份或恢复保证；Git 不保存数据库和媒体。公开到互联网之前，请理解上述边界；如要真的仅两人能访问，应另行增加服务端或网关校验。

## 验证

- `npm run typecheck`：Vue 与 TypeScript 类型检查。
- `npm run build`：类型检查和生产构建。
- `npm start`：启动生产模式，在浏览器验证 API 与静态页（见上文「生产模式本地验证」）。

浏览器验收：在桌面与双方手机普通浏览器走通入口、日历、上传、视频、双设备同步与移动布局；这不能代替真实 iPhone/Safari 或阿里云 2GB 机器测试，也未对所有配色做全面无障碍审计。

编辑器提示：本机 IDE 的旧 Vetur 诊断对 Vue 3 `<script setup>`、编译宏与现代模块解析有误报；当前 `vue-tsc`、生产构建与浏览器运行均通过。建议使用 Vue - Official（Volar）支持 Vue 3；本轮没有修改用户的全局插件设置或关闭校验来隐藏诊断。
