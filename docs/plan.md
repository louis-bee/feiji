# 我们的恋爱网站：设计与实施方案

日期：2026-09-30（2026-11-08 按代码现状更新）  
状态：首个可运行版本已完成（v1.2.2），实现登录、首页、日历、相册、纪念日、设置六个页面，并加入对方记录未读提示；远程部署与 Android 封装尚未执行。下文保留设计依据与历史取舍，实际实现与运行方式以 [README](../README.md) 为准。

实现取舍（已落地）：Vue 3＋TypeScript＋Fastify＋SQLite（better-sqlite3）＋sharp；业务时区默认 `Asia/Shanghai`，可在设置修改；暂不加入回复、愿望、歌曲卡、标签/地点等扩展。月历、图片灯箱与视频播放均采用轻量自建组件，日期使用原生 Intl 与纯日期函数（`shared/dates.ts`），未引入候选 UI/日期库（VCalendar、PhotoSwipe、Day.js 均未采用）。

开源与官方资料依据见 [research.md](research.md)。

## 1. 一页结论

已把它实现为一个**手机优先的双人生活手账**，不是功能很多的情侣社交平台。

- **核心体验：** 打开就看到“今天是我们在一起的第 N 天”，能快速写下今天、回看照片、知道接下来两个重要日子。
- **页面：** 登录、首页、恋爱日历、精选相册、纪念日、设置六个页面；移动端底部四项导航（首页/日历/相册/纪念日），登录与设置位于次级入口。
- **视觉已实现：** [A 双人飞行日志](design-options.md)，温暖纸色、航迹与原创企鹅插画；布局已按移动端优先＋PC 分栏落地。
- **内容已实现：** 首页、日历多条文字/图片/视频记录、相册、生日周年与自定义事件、设置；回复、标签/地点、愿望、歌曲卡等扩展未加入。
- **技术栈已落地：** Vue 3＋TypeScript＋Vite＋Vue Router＋Fastify＋SQLite（better-sqlite3）＋sharp；本地图片与视频文件；未使用 Day.js、VCalendar、PhotoSwipe，均以自建组件与原生 Intl 实现。
- **已定登录体验：** 选两人的昵称之一，前端对共用口令做简单校验（口令来自 `public/config.json`）。不实现后端认证；这只是页面入口门槛，不保证内容仅两人可见。
- **媒体范围：** 支持 JPEG/PNG/WebP/GIF 图片与 MP4/WebM/MOV 视频，不提供原片下载；不设业务容量指标，不规划扩容或额外存储服务。
- **部署策略：** 沿用现有阿里云 2GB 轻量服务器；在开发机构建前端，服务器提供静态资源和单进程 API；具体步骤见 [部署计划](deploy.md)，尚未远程执行。
- **开发预算：** 首版核心 Web 已完成；后续 Web 上线约 1.5～2.5 天、Android WebView 壳约 2～5 个有效人日（见第 9 节），均为估算而非工期承诺。

### 需要在对应阶段开始前确认

1. **个性化素材：** 后续需要时提供头像/照片；音乐如需精选内容，再提供偏好的歌手或曲目，不根据流派猜测具体喜好。
2. **内容与节奏：** 确认日历是否需要单层回复、是否采用愿望/歌曲卡等扩展；技术栈已确定为推荐组合（见第 5 节）。
3. **媒体兼容：** 用目标手机样片确认视频容器与编码；“普通视频”不代表浏览器能播放任意编码。此项不是要求先统计媒体容量。
4. **业务时区：** 已实现为 `Asia/Shanghai`，可在设置修改。
5. **实际部署时再检查：** 系统/CPU 架构、既有代理、运行时和 HTTPS 配置；当前不因服务器状态正常再要求排障或迁移，也不索取凭据。

**不再列为待选事项：** 前端密码、公历、当天第 1 天、图片与视频、无需原片下载、移动端优先兼容 PC、暂缓容量与备份规划。

“不提供原片下载”不自动等于“授权删除原始上传文件”。暂不增加原片归档产品功能，也不制定自动删除源文件规则，后续若需清理再明确处理方式。

## 3. 产品信息架构

### 3.1 页面与访问路径

| 页面 | 内容 | 核心操作 |
| --- | --- | --- |
| 登录 | 两个昵称/插画头像选项、一个口令输入框 | 选身份、进入；保留清晰错误反馈 |
| 首页 | 主照片（封面）、在一起天数、首页寄语、接下来两个重要日子、最近记录、精选媒体 | 记下今天、打开最近记录、查看相册 |
| 恋爱日历 | 周一起始月视图、日期标记、选中日记录列表、未读圆点 | 切月、回今天、补记、编辑、删除自己的记录 |
| 精选相册 | 图片/视频混合展示，手动精选与排序，按相册/未归类浏览 | 上传、写说明、关联日期、打开大图/播放视频、设为精选 |
| 纪念日 | 下一次发生日、倒计时、年度/一次性分类 | 新建、编辑、删除自定义事件；生日与周年自动派生 |
| 设置 | 昵称、生日、恋爱起始日、业务时区、首页寄语、封面图、退出入口 | 修改共同配置；不做复杂后台 |

移动端底部四项导航：首页 / 日历 / 相册 / 纪念日；登录与设置位于次级入口。PC 使用顶部导航与更宽的内容区，不仅把手机版等比例放大。编辑工具直接嵌入页面，不另做一套后台管理系统。

### 3.2 恋爱日历：先做好长期记录

- 一天可有多条记录，两人各自署名；同一天允许各写各的，不采用每天唯一一篇的覆盖模型。
- 记录使用正文＋图片/视频附件（正文最多 20000 字，附件最多 100 个媒体）；暂不做富文本编辑器、标题、标签/地点、公开评论和多级回复。
- 月视图只显示简洁标记：有记录、有媒体、重要日子；格子内不播放视频。
- 点日期后，手机在下方/抽屉显示记录，PC 在右侧显示记录。没有内容时显示“为这一天留一句话”。
- 可补记过去的日期；记录日期与实际创建时间分开保存，不仅按创建时间归档。
- 默认 UI 只展示当前所选身份的编辑入口，相册与纪念日共同维护。这只是防误操作约定；前端身份可修改，不是真实身份或权限隔离。
- 保存失败时不清空编辑框；媒体上传未完成不能假装保存成功。页面离开时提示未保存内容。
- 两人同时编辑同一共享条目时做版本检查，冲突提示刷新或另存，不静默覆盖。
- 已加入未读提示：对方新增或编辑的记录在对应日期以未读圆点标注，选中当天即标记已读；自己写或改的不算未读。
- 二期再考虑对记录回复、搜索、“去年的今天”、标签，不扩展成即时聊天系统。

### 3.3 精选相册：图片与视频共同记录

- 首页呈现人工精选照片或视频封面，视频不自动播放。
- 相册可自定义命名，预置「日常碎片」默认相册；一项媒体可被多条日历记录引用，并至多属于一个相册。
- 图片与视频混排；视频卡片显示播放标记，封面使用占位（不服务端截帧、不自动获取时长），不让整个列表预加载视频。
- 图片使用自建灯箱；视频使用独立原生播放器，不把图片灯箱或 sharp 当作视频处理库。
- 手机支持触摸、行内播放和横竖屏；PC 支持鼠标、键盘及合适的大图/视频展示宽度。
- 上传提供进度、取消、失败重试、批次结果；单个文件失败不要求全部重传。
- 文件落盘成功后再标为可用；用户删除操作需确认，关联媒体不能误删。暂不规划自动定期清理。
- **不提供原片下载按钮或专用下载接口。** 浏览器为了展示/播放仍会获取媒体字节，隐藏下载按钮不是防下载措施。
- 不承诺原片归档、自动备份或自动删除原始上传文件；这些均不在本期已确认范围。

### 3.4 纪念日与生日

- 区分一次性事件（某次旅行出发日）与每年重复事件（生日、恋爱周年）。
- 纪念日卡片显示事件名、下一次日期、距离天数；当天显示“就是今天”，不显示“还有 0 天”。
- 排序依据下一次发生日，不按原始年份排序。生日不应在今年已过后显示负数倒计时。
- 已结束的一次性事件移到过去事件区，不自动变成年度事件。
- 100 / 365 / 1000 天可以作为里程碑，但“365 天”和“周年”不能混为一谈，闰年会产生差别。
- 只做站内倒计时，不做邮件、微信或浏览器通知；网页倒计时本身不会主动推送提醒。

## 4. 已选视觉：A「双人飞行日志」

用户已确认采用 A，不再进行四套风格选型。配色与角色细节见 [视觉文档](design-options.md)，其他方案保留为历史参考；未自动批准原混合风格建议。

- 暖纸白、深墨蓝、少量蜂蜜黄，以真实照片、细航迹和清晰文字为主；具体颜色与字体随布局验证。
- 飞机/旅行为主要视觉语言；企鹅为我的形象线索，蜜蜂作配饰；羽毛球承载共同爱好，悬疑/电影/阅读融入内容。
- 企鹅建议原创，不直接复制腾讯/QQ 官方完整形象或标识，不暗示公司官方项目。
- 手机首屏天数和“记下今天”可见，PC 使用分栏，导航保持首页/日历/相册/纪念日。
- 角色不能压过真实照片，不加入常驻粒子、3D 飞机、自动音乐或强制解谜。
- 视觉已落地：暖纸色、航迹与原创企鹅/山野插画由 `web/components/JourneyArt.vue` 等自建组件呈现，不再处于“待制作布局”阶段。

## 5. 技术架构与取舍

### 5.1 已实现结构

浏览器中的 Vue SPA（前端口令入口）→ 同域 HTTPS 反向代理 → 静态资源 / `/api/*` / `/media/*` → 单个 Node.js API → SQLite 与媒体文件目录。

- Vue 3＋TypeScript＋Vite＋Vue Router；API 负责跨设备持久化，并非因为前端校验就取消后端。
- 状态管理使用组合式函数与响应式 store（`web/store.ts`），未引入 Pinia。
- 日期使用原生 Intl 与纯日期函数（`shared/dates.ts`）；月历、图片灯箱与视频均为自建组件/原生播放器，未使用 Day.js、VCalendar、PhotoSwipe。
- API 使用 Fastify 5，JSON Schema 校验入参（`server/schemas.ts`），依赖版本配套锁定。
- SQLite 驱动为 `better-sqlite3`；每张表用 `id + JSON payload` 存储，schema 版本经 `user_version` 保护升级，未引入 ORM。
- 图片处理使用 sharp（单线程、缓存 32MB、解码像素上限 4000 万）；视频流式落盘和读取，不把媒体 base64 存数据库，也不把整个视频读入内存。
- 没有 SEO、即时聊天需求，不引入 SSR 或 WebSocket。
- 单 API 进程、一个数据库文件（WAL 模式＋`busy_timeout`）处理双人写入；备份当前不实施。

### 5.2 为什么不是更重的方案

- MySQL/PostgreSQL：当前不需要多实例写入，先不增加常驻服务。
- Redis：无分布式会话、队列需求。
- Docker：可选，若已有容器部署就沿用，否则 systemd 更直接。
- PocketBase：是另一条后端路线；内置认证不是当前前端入口的必需品，不与自建 API 混搭。
- 仅静态网页＋localStorage：无法实现两人的多台设备共享记录和媒体；localStorage 不能代替业务数据库。

### 5.3 已实现：前端固定口令简单校验

1. 入口提供两个昵称选项和同一个口令；口令来自 `public/config.json` 的 `entryPassword`（默认 `0611`），构建后直接改该文件即可换口令，无需重新构建。前端比较通过后进入页面，路由守卫只做 UI 拦截。
2. 用 `sessionStorage`（key `our-flight-entry`）保存当前标签页所选身份 `her`/`him`；刷新保留，退出清除。不做后端 Cookie/会话（另有一个 `feiji_actor` Cookie 仅用于后端访问日志，不参与鉴权）。
3. 两个固定身份 `her`/`him` 用来署名，昵称不是数据库主键；后端仅检查该值是否属于允许值，不声称验证了真实身份。
4. 不新增 `/api/session` 或服务端口令校验，不做注册、找回密码、第三方登录或角色系统。
5. HTTPS、参数校验、路径约束和上传错误处理仍保留，用于传输与程序正确性，不等于用户鉴权。

**明确的功能边界：**

- 前端资源可被下载，密码或比较逻辑可被找到；混淆、哈希、构建时环境变量都不能把前端校验变成可靠认证。
- 通过标记和身份可以被修改，路由守卫可以绕过；在没有其他访问控制时，API 可被直接读写，媒体链接可被直接访问，包括上传和删除操作的滥用风险。
- 退出只清理本地界面状态，不撤销 API 或媒体访问权限；不以“退出后外部无法访问”作为验收标准。
- `robots.txt`、不展示链接、随机媒体 ID、关闭目录索引和隐藏下载按钮均不保证私密。

按用户决定采用此简化方案，不再将后端认证列为待批准事项；同时不再描述为“技术上仅两人可见的私密网站”。如果以后要真正限制访问，再单独增加服务端或网关校验。

## 6. 数据与接口（已实现）

以下是当前代码实际落地的数据模型与 API，替代早期的概念草案。

### 6.1 数据模型

SQLite（better-sqlite3，WAL 模式）：每张表结构统一为 `id TEXT PRIMARY KEY` + `payload TEXT`（经 `json_valid` 校验的版本化 JSON），schema 版本经 `user_version` 保护升级（当前版本 2）。共 7 张表：

| 表 | 主要字段（JSON payload） | 规则 |
| --- | --- | --- |
| `settings` | `startDate`、`timezone`、`coverMediaId`、`intro`、`version` | 单条记录（id=`site`）；口令只在前端 `public/config.json`，不建服务端认证数据 |
| `profiles` | `id`(`her`/`him`)、`nickname`、`birthday` | 两条：飞机 `2006-10-25`、大黄丰 `2004-08-11`；昵称/生日可改，固定 ID 不变 |
| `entries` | `id`、`date`、`authorId`、`body`、`mediaIds[]`、`version`、`createdAt`、`updatedAt` | 同一天多条；正文最多 20000 字、附件最多 100 个；`mediaIds` 直接挂载，不再有 `entry_media` 关联表 |
| `media` | `id`、`kind`(image/video)、`name`、`mime`、`width/height`、`size`、`albumId`、`caption`、`date`、`featured`、`version`、存储键 `originalFile/viewFile/thumbFile` | 存储键仅在服务端使用，DTO 输出 `/media/:id/view`、`/media/:id/thumb`，不返回磁盘绝对路径 |
| `albums` | `id`、`name`、`description`、`version` | 预置「日常碎片」；无封面媒体字段，封面由内容决定 |
| `events` | `id`、`title`、`date`、`repeat`(yearly/once)、`note`、`version` | 只做公历；生日与恋爱周年由前端按 profile/settings 派生（`builtIn`），不入库 |
| `reads` | `actorId`、`entryId`、`version`、`readAt` | 一方对对方记录的已读标记，支撑日历未读圆点；schema v2 新增 |

纯日期存 `YYYY-MM-DD`，用户已给出生日年份，不将其丢弃；创建时间存 UTC 时间戳。展示按配置时区，删除共享媒体前检查引用（被日记或首页封面引用时返回 409）。

记录/媒体/相册/事件更新都带 `version` 做乐观锁，不匹配返回冲突；已建立 `entries_date` 与 `media_album` 索引。当前是小站全量快照加载，未实现分页或海量数据优化。

### 6.2 API 路由

| 接口组 | 实际路由 |
| --- | --- |
| 健康检查 | `GET /api/health` |
| 全量快照 | `GET /api/bootstrap`（settings、profiles、entries、media、albums、events、reads 一次返回） |
| 设置/资料 | `GET /api/profiles`、`PUT /api/settings`、`PUT /api/profiles/:id` |
| 记录 | `POST /api/entries`、`PATCH /api/entries/:id`、`DELETE /api/entries/:id?version=` |
| 已读 | `POST /api/reads`（选中某天即把对方该日记录标为已读） |
| 相册 | `POST /api/albums`、`PATCH /api/albums/:id`、`DELETE /api/albums/:id?version=`（非空相册禁止删除） |
| 纪念日 | `POST /api/events`、`PATCH /api/events/:id`、`DELETE /api/events/:id?version=` |
| 媒体 | `PATCH /api/media/:id`、`DELETE /api/media/:id?version=`、`GET /media/:id/:variant`（`view`/`thumb`，支持 Range） |
| 上传 | `POST /api/uploads`（multipart，字段 `albumId`/`date`＋文件；流式保存与处理） |

入口校验和退出由前端完成，没有 `/api/session`。API 使用统一错误格式、JSON Schema 参数白名单；正文按文本渲染，不允许任意 HTML。无后端身份验证时，这些 API 与媒体路径不具备用户访问权限限制，CORS/Origin 校验也不能阻止外部客户端直接调用。

## 7. 媒体、日期与服务器的关键细节

### 7.1 图片与视频策略

**范围已定，具体兼容参数是建议，不把“暂不考虑大小”理解成硬件和网络无限制。**

- 图片兼容：接受 JPEG、PNG、WebP、GIF（实际解码校验）；非 GIF 生成长边不超过 2000px 的 WebP 浏览图和 480px 缩略图并校正方向，GIF 保留动画仅生成缩略图。HEIC、Live Photo 不承诺自动转换。
- sharp 默认移除 EXIF 等元数据，仅对处理后的输出成立，不保证所有源文件脱敏；解码像素上限 4000 万。
- 视频兼容目标：MP4 容器＋H.264 视频＋AAC 音频（或无音轨）。MP4 后缀不保证内部编码一致，MOV/HEVC 等需单独验证，不以改扩展名代替转码。
- 一期建议不做服务端转码、HLS、自适应清晰度或第三方视频云。兼容性检测失败时明确提示重新导出兼容格式，不假装上传成功即可在另一台手机播放。
- 采用原生 `video` 的 controls、playsinline，用户点击播放，不自动播放；列表显示封面或占位，播放器按需加载。图片灯箱为自建组件，未使用 PhotoSwipe。
- 视频仅做容器级探测（WebM 的 EBML 头 / MP4 的 `ftyp`），不做编码级完整探测、不读时长、不截帧、不引入 ffprobe。播放器错误提供可理解的提示。
- 播放文件通过支持 Range 的标准文件服务输出，验证 HEAD、206、Content-Range 及无效范围的 416；不手写不完整的分段读取实现。
- 视频流式上传/落盘/读取，避免整段读入内存；先整文件重试，不默认实现分片上传或断点续传。支持播放 Range 不等于支持断点上传。
- 当前不确定单文件业务限额、总空间配额或扩容预算，移除原 15MB/10 张预设。实现时检查代理/上传库默认限制与超时并协调，资源不足应明确失败，不能承诺任意大小均可上传。
- 所有媒体存现有服务器，文件目录与应用产物分离，不开启目录索引，不把数据库放进静态目录；不开放目录索引仍不等于链接受保护。
- 不提供原片下载入口，不自动删除源文件。视频用于播放的文件仍必须保存，不因“无需下载原片”而删除。
- 列表懒加载、宽高占位，首屏主照片优先显示；不做媒体离线缓存。Cache-Control 可减少不期望的缓存，但不是鉴权。
- sharp 单线程并限制缓存；上传同时最多处理 2 个请求，支持进度、取消、失败反馈，不引入 Redis 队列。

视频格式与 HTTP Range 的新增官方依据见 [调研补充](research.md#7-视频支持补充调研2026-09-30)。

### 7.2 日期规则

- 业务时区默认 `Asia/Shanghai`，可在设置修改；旅行时不随设备时区跳变。
- **已确认：公历，从 `2026-06-11` 开始，当天算第 1 天。** 页面统一用“在一起第 N 天”，计算为业务日期差＋1，不把日期口径改成累计飞行小时。
- 大黄丰生日 `2004-08-11`，飞机生日 `2006-10-25`；每年按公历月日重复，年份保留。
- 先将当前时间转换为业务时区的年月日，再计算日期序号差；不能直接把时间戳差除以 24 小时。
- 避免 `new Date('YYYY-MM-DD')` 的 UTC 解析与本地显示混用导致偏移。
- 年度事件目标日严格早于今天才滚动到下一年；当天显示“就是今天”。
- 两个已知生日不涉及 2 月 29 日；若以后新增该日期的年度事件，再要求选择平年策略，不默认推断。
- 不引入农历换算库或农历设置。
- 手机休眠恢复、页面重新可见与跨午夜时重算；开始日若在未来，提示修正或显示距离开始天数。

### 7.3 沿用现有阿里云服务器

用户已确认现有 2GB 轻量服务器正常、能满足基本需求。本轮不排障、不扩容、不另选云平台，也不做媒体容量预算；这不是已经测试过无限大小文件的承诺。

实施时仅保留轻量化约定：

- 前端在开发机或 CI 构建，线上不长期运行 Vite 开发/预览服务器。
- 单 API 进程，媒体流式读写，图片受限并发，不在 2GB 机器上默认跑视频转码。
- `better-sqlite3`、sharp 等原生依赖按目标系统和 CPU 安装，不能上传 macOS 的 `node_modules` 当作 Linux 依赖。
- 未来有实际容量需求再加存储，只让媒体存储逻辑集中管理，不提前引入对象存储适配层。
- 实现时处理磁盘不足、超时和部分上传文件，避免错误成功提示；不把暂缓容量规划变成忽略异常。

## 8. Web 部署与 Android 应用路线

实施顺序已明确：**先完成 Web 正式部署和双方真实浏览器使用，再制作 Android WebView 薄壳。**完整步骤、风险门槛、原生文件选择、视频全屏、返回键、错误页、签名与设备验收见 [Web 上线与 Android 封装计划](android-app-plan.md)；面向 `feiji.brotherlouis.site` 的具体部署命令见 [部署计划](deploy.md)，尚未远程执行。

### Web 部署

1. 域名已确定为 `feiji.brotherlouis.site`；实际操作前确认服务器系统、架构、磁盘、现有代理和端口；复用 Nginx/Caddy，不重复占用 80/443。
2. 在服务器重新安装匹配 Linux 与 CPU 的锁定依赖并构建，不复制 macOS 的 `node_modules`，不在线运行 Vite 开发服务。
3. API 绑定回环地址，通过正式域名 HTTPS 代理；持久 `DATA_DIR` 使用发布目录外的绝对路径，更新代码不覆盖数据库和媒体。
4. 低权限用户运行单服务，交给 systemd 或已有进程管理器；HTTP 跳转 HTTPS，代理保持视频 Range。
5. 电脑、双方手机普通浏览器验收入口、日历、上传、视频拖动、两设备同步、重启持久化和移动布局。
6. 公网部署前再次确认前端口令风险：保持现状需接受 API/媒体可被绕过访问；若改变为服务端/网关校验，作为单独需求处理。

### Android WebView 薄壳

1. 只有正式 HTTPS Web 稳定后才创建 `android/` 工程，固定正式域名；浏览器访问方式不变。
2. 使用无 ActionBar 的单 Activity WebView，保留系统状态栏；站内域名留在 WebView，外链交给系统浏览器，明文 HTTP 和未知协议默认拒绝。
3. 接入 HTML 文件多选、取消回调、原生视频全屏、WebView 历史返回、错误/重试页和 Activity 状态恢复；首版不开放通用 JS 桥，不加入相机直拍、通知或离线写入。
4. 双方真实 Android 手机验收上传、视频、返回键、前后台、弱网、刘海与手势导航；先生成签名 release APK 侧载，应用商店和 TWA 后置。
5. 网页业务更新通常只发布 Web；域名、图标、文件选择、视频全屏和原生权限变化才需要更新 APK。

### 暂缓：备份、扩容和额外维护体系

- 按用户要求移出一期，不配置异机备份、备份周期、恢复演练、对象存储或付费服务。
- 不承诺 RPO/RTO，不把“存在服务器上”或“用了 Git”描述成已经备份；故障或误删可能无法恢复。
- 若以后启用备份，应同时覆盖数据库和媒体，并使用 SQLite 一致快照，而非直接复制正在写入的数据库。相关技术资料保留在调研文档，不是当前任务。
- 不创建定时任务或自动化；新增维护功能时再确认范围。

### 必测清单

- 日期：开始当天为第 1 天、开始前、月末、跨年、两个生日当天及已过生日、业务时区、页面过午夜。

- 图片：竖图方向、透明 PNG、GIF、解码失败、重复上传、网络中断、磁盘不足、删除仍被引用的媒体。
- 视频：双方手机和 PC 实测播放/声音/暂停/拖动/行内与全屏，验证 206/416、取消上传、不兼容编码提示；列表不自动播放或加载全部视频。
- 响应式：360～430px 手机、平板宽度与 1280px 以上 PC；触摸、鼠标、键盘、横竖屏、键盘弹起、长昵称和错误反馈。
- 发布：Linux 原生依赖可用，停止重启仍有数据，更新不覆盖媒体；不含备份恢复验收或无损灾难恢复承诺。
